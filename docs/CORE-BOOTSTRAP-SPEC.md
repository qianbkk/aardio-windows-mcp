# 核心自举层与扩展层架构规范 (Core Bootstrap Specification)

> **版本**: 1.0 (规范化工程定稿)  
> **状态**: 严密论证 & 已验证  
> **适用**: AI Agent 自动化系统、Windows 底层运维与自进化工具链

---

## 1. 架构分层公理与职责边界

本系统在设计上严格遵循**“最小完备自举核心（Minimal Bootstrap Set）+ 可插拔高频工具集（Pluggable Ext Set）”**的解耦哲学：

```
┌────────────────────────────────────────────────────────────────────────┐
│                        MCP Bridge 协议适配层                            │
│                  (22 个标准 MCP 工具，动态探针与自愈生命周期)             │
└───────────────────────────────────┬────────────────────────────────────┘
                                    │ HTTP RPC (127.0.0.1:42179)
                                    ▼
┌────────────────────────────────────────────────────────────────────────┐
│                   【核心层】main.aardio (31 端点)                       │
│  · 定位：图灵完备自举母机、Windows 底层 OS/硬件抽象原语、全权动力源    │
│  · 目标：提供 AI 凭自身完成“自我造血、自我编译、全系统控制”的完备能力  │
│  · 依赖：仅依赖静态嵌入的标准库，永远不依赖 ext-tools.aardio          │
└───────────────────────────────────┬────────────────────────────────────┘
                                    │ loadcodex 动态热挂载
                                    ▼
┌────────────────────────────────────────────────────────────────────────┐
│                 【扩展层】ext-tools.aardio (19 端点)                   │
│  · 定位：高频实用工具预制件、语法糖集合                              │
│  · 目标：为日常任务提供免写脚本的直接调用便利 (图片/二维码/RSS/天气等)  │
│  · 依赖：完全可插拔，即使彻底删除，核心层亦 100% 正常运行             │
└────────────────────────────────────────────────────────────────────────┘
```

## 2. 核心层自举闭环理论证明 (Self-Evolution Completeness)

**核心命题**：  
> *AI 是否能在完全无外界干预、无人类点击、无第三方辅助工具的前提下，仅依靠核心层的 31 个端点，实现任意新能力的扩展、源码修改、重编译、服务重载与可用性验证？*

**证明过程（7 步自进化闭环）**：

| 阶段 | 任务 | 调用的核心端点 | 执行逻辑与闭环证据 |
|:---|:---|:---|:---|
| **Step 1: 代码审视** | 定位目标工程与源码 | `GET /api/find-files`<br>`GET /api/eval` | 通过高速文件遍历定位 `ext-tools.aardio`，利用 `eval` 中的 `string.load` 读取源码内容进上下文。 |
| **Step 2: 动态热验证** | 验证新 aardio 代码正确性 | `GET /api/eval` | 在不重编译的情况下，直接将拟新增的函数体传入 `eval` 进行单元测试与异常排错（直接调用 1000+ 标准库）。 |
| **Step 3: 源码写入** | 持久化更新源码文件 | `GET /api/eval` | 调用 `string.save(".../ext-tools.aardio", newCode)` 将新端点代码原子写入磁盘。 |
| **Step 4: 独占锁释放** | 清除占用产物的旧进程 | `GET /api/processes`<br>`GET /api/processes/kill` | 扫描占用 `rpc-server.exe` 的旧进程 PID 并强制终止，确保编译目标文件句柄处于可写状态。 |
| **Step 5: 无人值守编译** | 触发编译生成新 EXE | **双轨机制**：<br>① `GET /api/exec`<br>② **GUI 兜底原语** | **轨 ① (自动化管线)**：直接 `exec` 驱动 `rebuild-rpc-server.py`。<br>**轨 ② (原生 GUI 闭环)**：通过 `launch` 打开 IDE，`window/topmost` 锁定窗口，`clipboard/set` + `keyboard` 发送路径并按 F7 编译，`screenshot` 视觉确认。 |
| **Step 6: 服务唤醒与验证** | 静默重启并做健康巡检 | `GET /api/exec-bg`<br>`GET /api/health` | `exec-bg` 静默启动新生成的 EXE，轮询 `/api/health` 确认服务重新就绪。 |
| **Step 7: 动态元发现** | 获取新能力定义 | `GET /api/help` | 调用 `/api/help`，新挂载的扩展端点自动被反射读取，AI 即可直接调用新功能。 |

**结论**：核心层端点构成了**严格闭环**，数学与工程层面均证明其具备完全独立的自更新与自拓展能力。

## 3. 核心层 31 端点分类与正交性逐项审查

为了杜绝功能冗余，核心层 31 个端点按职责正交拆分为五大不可替代模块：

### 模块 A：自举动力源 (Bootstrap Engines) — 3 项
- `GET /api/eval`：**运行时全权**。动态执行任意 aardio 语法与库，是整个系统动态无限拓展的终极底座。
- `GET /api/exec`：**操作系统全权（同步）**。同步捕获 shell 输出，执行诊断脚本或短时命令。
- `GET /api/exec-bg`：**操作系统全权（异步）**。用于启动后台常驻任务或编译管线，避免 HTTP 超时挂起。

### 模块 B：系统与进程控制 (Process & OS Lifecycle) — 6 项
- `GET /api/launch`：通过 Win32 `process` 原生拉起程序，完全规避 CMD 黑框。
- `GET /api/processes`：进程列表（含内存、PID、排序），用于探测系统占用。
- `GET /api/processes/kill`：解除文件独占锁，是自动化重编译发布的前置必备原语。
- `GET /api/system-info`：获取系统架构、用户主目录、临时目录等关键上下文。
- `GET /api/system/stats`：WMI 实时抓取 CPU、内存负载与各盘剩余空间，防止编译时磁盘耗尽。
- `GET /api/net-info`：多网卡与局域网 IP 识别，支持多机跨网络编排。

### 模块 C：文件与持久化底座 (Filesystem & Persistence) — 5 项
- `GET /api/find-files`：高性能通配符与递归搜索，AI 定位库文件与配置的关键工具。
- `GET /api/files/dirsize`：统计目录整体大小与文件数，用于构建产物大小检查与清理。
- `GET /api/hosts/read`：直接读取系统底层 hosts 规则，提供网络基础设施透视。
- `GET /api/sqlite/query`：提供跨语言的结构化本地持久化能力（内置 SQLite 驱动）。
- `GET /api/http`：底层 HTTP 代理通道，用于跨节点数据上报或轻量外部请求。

### 模块 D：Computer Use 桌面操作视听原语 — 14 项
> **为什么必须在核心层？**  
> aardio IDE 官方不提供 CLI 编译器，将 aardio 源码编译为单文件 EXE **必须依赖桌面交互（按 F7、处理弹窗）**。因此桌面操作能力是自举闭环中的核心硬依赖，绝非普通附加工具。

1. **视觉反馈闭环**：
   - `GET /api/screenshot`：全屏/窗口截图，供 AI 识别界面状态、对话框、错误信息。
   - `GET /api/screen/info`：物理分辨率、多屏拓扑与 DPI 缩放基准。
   - `GET /api/screen/pixel`：高精度取色，用于判定按钮状态、指示灯与渲染结果。
2. **鼠标精确交互**：
   - `GET /api/mouse/pos`、`move`、`click`、`scroll`、`drag`：构成完整的指针控制闭环。
3. **窗口精确调度**：
   - `GET /api/window-list`、`window-info`：枚举句柄、类名、标题与坐标。
   - `GET /api/window/topmost`：强制置顶指定窗口，防止因失焦导致快捷键投递失效。
4. **键盘与剪贴板绕障**：
   - `GET /api/keyboard`：模拟全局热键（F7、Ctrl+O、Enter）。
   - `GET /api/clipboard`、`clipboard/set`：**关键绕障工具**。在输入文件路径时，若用键盘敲字符极易被中文输入法（微软拼音等）拦截变成汉字拼音候选；通过剪贴板直接写入再发送 `Ctrl+V`，可 100% 规避输入法干扰。

### 模块 E：反射自省与路由 (Reflection & Routing) — 3 项
- `GET /api/health`：服务心跳探针。
- `GET /api/help`：自动合并核心与扩展层的端点文档，供客户端自适应反射。
- `GET /`：根路由，提供基础运行状态展示与引导。

## 4. 边界审查：是否存在可以降级到扩展层的冗余？

在本次审查中，对几个潜在“疑似边缘”端点进行了严密论证：

### 审查 1：`sqlite/query` 是否应该下沉到扩展层？
- **论证**：
  1. `sqlite` 在 aardio 中属于内置**标准核心库**，不依赖任何第三方二进制或 IDE 扩展库；
  2. AI 自身在本地长期记忆、状态追踪、任务队列编排中，SQLite 是唯一免配置、零维护的标准持久化引擎；
  3. 保留在核心层确保了即便扩展层被清空，AI 依然具备结构化数据存储能力。
- **裁决**：**保留在核心层**。

### 审查 2：`hosts/read` 与 `files/dirsize` 是否冗余？
- **论证**：
  1. 它们完全基于标准库 `fsys` 和 `string.load`，代码体积极小（各不足 15 行），未引入额外开销；
  2. `dirsize` 是工程构建前验证空间与清理的重要判据；
  3. `hosts/read` 是系统级基础设施诊断原语，与扩展层纯业务工具（如天气、二维码）性质完全不同。
- **裁决**：**保留在核心层**。

### 审查 3：扩展层与核心层的分水岭准则
任何符合以下特征的端点，**坚决放入扩展层 (`ext-tools.aardio`)**，严禁污染核心层：
- 属于业务级功能（如图片加水印、二维码生成、天气预报、翻译、密码本）；
- 具备可替代性，删除后完全不影响 AI 对系统底层与 IDE 的操控能力；
- 需要频繁增减字段或修改业务逻辑。

## 5. 总结与工程规范

1. **绝对纯粹**：核心层（31 端点）已精炼为一套最小且完备的 Windows OS 原生操作系统底座。
2. **零硬编码**：核心层所有路径、日志均使用 `%LOCALAPPDATA%` 和动态相对路径，不留任何环境绑定。
3. **无限拓展**：核心层的自举闭环经过实测验证，AI 可仅凭核心能力创造、编译并发布任意新的业务工具。
